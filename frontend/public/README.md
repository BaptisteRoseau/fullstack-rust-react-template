# public

Static files served as-is at the site root by Vite: no bundling, stable URLs. Reference them by
absolute path (e.g. `/logo192.png`). An image that should be bundled and fingerprinted instead goes
in `src/img/`.

```txt
public/
├── favicon.ico, logo192.png, logo512.png   # app icons
├── _redirects                              # Netlify SPA redirect rules
├── mockServiceWorker.js                    # MSW service worker, generated by `msw init` — do not hand-edit
├── robots.txt                              # GENERATED — do not hand-edit
├── sitemap.xml                             # GENERATED — do not hand-edit
├── site.webmanifest                        # GENERATED — do not hand-edit
├── llms.txt                                # GENERATED — do not hand-edit
└── .well-known/
    └── security.txt                        # GENERATED — do not hand-edit
```

The five generated files come from `bun run seo:generate`, driven by `seo.config.ts`. `bun run
seo:check` fails if a committed file drifts from a fresh render. The committed copies carry the
placeholder origin `http://localhost:3000`; a Vite plugin rewrites them into `dist/` at build time
using `SEO_SITE_URL`, so deployments ship absolute URLs for the real host.

`security.txt` ships with the placeholder contact `security@example.com` and a pinned `Expires`
timestamp — both must be replaced per deployment, or security reports go nowhere and the file
expires.
