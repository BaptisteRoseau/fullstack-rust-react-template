# `public/`

Static files served as-is at the site root by Vite (no bundling, stable URLs).

- `favicon.ico`, `logo192.png`, `logo512.png` — app icons.
- `_redirects` — Netlify SPA redirect rules.
- `mockServiceWorker.js` — the MSW service worker (generated by `msw init`; powers in-browser API mocking in dev). Don't edit by hand — regenerate via MSW if upgrading.

## Generated SEO and agent files — do not hand-edit

These are produced by `bun run seo:generate` from `seo.config.ts`. Edit the config or
the templates in `scripts/generate-seo-files.ts`, then regenerate and commit the result.
`bun run seo:check` fails if a committed file drifts from a fresh render.

- `robots.txt` — crawler rules. Allows all AI crawlers by default; the opt-out stanza ships commented out.
- `sitemap.xml` — one `<loc>` per entry in `PUBLIC_PATHS`. That list opts _in_, so a new route stays unpublished until it is added there.
- `site.webmanifest` — web app manifest, linked from `index.html`.
- `llms.txt` — [llmstxt.org](https://llmstxt.org/) summary for LLM agents.
- `.well-known/security.txt` — [RFC 9116](https://www.rfc-editor.org/rfc/rfc9116.html) security contact.

The committed copies carry the placeholder `http://localhost:3000` origin. At build time
the `seo-files` Vite plugin rewrites them into `dist/` using `SEO_SITE_URL` (falling back
to `VITE_APP_APP_URL`), so deployments ship absolute URLs for the real host:

```sh
SEO_SITE_URL=https://example.com bun run build
```

`security.txt` ships with the placeholder contact `security@example.com` — **replace it**
per deployment via `SEO_SECURITY_CONTACT`, or security reports go nowhere. `Expires` is a
pinned timestamp in `seo.config.ts`, not a computed offset; bump it before it lapses.

Reference these by absolute path (e.g. `/logo192.png`). Assets that should be bundled/fingerprinted
go in `src/assets/` instead.
