# Add a database migration

Migrations live in [crates/database/migrations](../../../crates/database/migrations), numbered and
applied in order. Never edit a migration that is already committed — add a new one.

Read [crates/database/README.md](../../../crates/database/README.md) for the schema conventions.

## 1. Install the CLI once

```bash
cargo install sqlx-cli
```

## 2. Create the pair

Run from `crates/database`:

```bash
sqlx migrate add -rs <name>
```

`-r` creates the reversible `.up.sql` / `.down.sql` pair, `-s` keeps the sequential numbering.

## 3. Write the up migration

Follow the schema conventions:

```sql
id UUID UNIQUE NOT NULL DEFAULT uuidv7(),
-- ...
PRIMARY KEY(id),
```

Do **not** add `created_at` or `updated_at` columns by hand. A trigger adds and maintains them for
every new table, so Postgres keeps them current on its own.

Add an index for any column you will filter or join on.

## 4. Always write the down migration

Even when it ends up empty, the `.down.sql` file must exist. A failed migration is rolled back
automatically, and a missing rollback leaves the database half-migrated.

## 5. Regenerate the Rust models

[generated_models.rs](../../../crates/database/src/generated_models.rs) is generated by `sql-gen`.
Never edit it by hand; put hand-written types in `src/models.rs` instead.

```bash
./scripts/build_database_rust_models.sh
```

## Checklist

```bash
cargo test -p database --all-features    # runs the migrations against a container
```

- [ ] A `.down.sql` exists, even if empty.
- [ ] No committed migration was edited.
- [ ] `generated_models.rs` was regenerated, not hand-edited.
- [ ] Columns used in a `WHERE` or `JOIN` have an index.
